# 设计模式

设计模式面试不要只背定义，重点是能说清楚：

- 这个模式解决了什么变化点
- 项目里哪里用过或框架哪里用了
- 它带来的收益和代价是什么
- 如果不用这个模式，代码会出现什么问题

## 学习顺序

建议优先掌握以下模式：

- 策略模式：业务分支替代、支付渠道、模型路由、规则执行
- 工厂模式：对象创建解耦、不同实现统一入口
- 模板方法模式：固定流程 + 可变步骤
- 责任链模式：校验链、过滤链、审批链、风控链
- 代理模式：AOP、事务、权限、日志、远程调用
- 单例模式：全局唯一资源、配置、连接池管理

## 面试答题模板

回答设计模式题时，可以按四段说：

1. 先说明模式目的：它解决的是对象创建、流程复用、行为扩展还是对象协作问题。
2. 再说明项目场景：例如支付渠道、模型调用、校验链、异步事件、AOP 切面。
3. 说明收益：降低分支复杂度、隔离变化、提升扩展性、减少重复代码。
4. 补充代价：类数量增加、调用链变长、过度设计会降低可读性。
