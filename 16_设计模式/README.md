# 设计模式

设计模式面试不要只背定义，重点是能说清楚：

- 这个模式解决了什么变化点
- 项目里哪里用过或框架哪里用了
- 它带来的收益和代价是什么
- 如果不用这个模式，代码会出现什么问题

## 学习顺序

建议优先掌握以下模式：

- 策略模式：业务分支替代、支付渠道、模型路由、规则执行
- 工厂模式：对象创建解耦、不同实现统一入口
- 模板方法模式：固定流程 + 可变步骤
- 责任链模式：校验链、过滤链、审批链、风控链
- 代理模式：AOP、事务、权限、日志、远程调用
- 单例模式：全局唯一资源、配置、连接池管理

## 面向对象设计原则

参考 LearningNotes 的设计模式笔记，设计模式前应先掌握常见设计原则。面试时不要只背缩写，要能解释它们如何约束代码变化。

- 单一职责原则 SRP：一个类只保留一个引起它变化的原因。Service 里不要同时堆业务编排、参数转换、远程调用和持久化细节。
- 开闭原则 OCP：对扩展开放，对修改关闭。策略模式、工厂模式、责任链模式都常用于减少新增业务时修改主流程。
- 里氏替换原则 LSP：子类应该能替换父类且不破坏语义。接口实现不能靠抛异常来规避父接口契约。
- 依赖倒置原则 DIP：高层模块依赖抽象，不依赖具体实现。Spring 的接口注入、多模型客户端抽象、Repository 抽象都符合这个原则。
- 接口隔离原则 ISP：不要强迫调用方依赖它不用的方法。大接口应按场景拆成小接口。
- 最少知识原则 LKP：只和直接朋友通信，减少链式对象访问和跨层调用。
- 优先组合而非继承：Spring 生态大量通过组合、代理、后置处理器扩展行为，避免继承层级过深。

## 和 Spring 源码的关系

Spring 源码本身就是设计模式的综合应用：

- 模板方法：`AbstractApplicationContext.refresh()` 固定容器刷新流程，子类扩展细节。
- 工厂模式：`BeanFactory`、`FactoryBean`、`ObjectFactory` 统一对象创建。
- 代理模式：Spring AOP、事务、`@Async` 都依赖代理。
- 责任链模式：Spring Security Filter Chain、Spring MVC HandlerInterceptor。
- 适配器模式：`HandlerAdapter` 让不同类型 Handler 能被 `DispatcherServlet` 统一调用。
- 观察者模式：`ApplicationEventPublisher` 和 `ApplicationListener`。

## 面试答题模板

回答设计模式题时，可以按四段说：

1. 先说明模式目的：它解决的是对象创建、流程复用、行为扩展还是对象协作问题。
2. 再说明项目场景：例如支付渠道、模型调用、校验链、异步事件、AOP 切面。
3. 说明收益：降低分支复杂度、隔离变化、提升扩展性、减少重复代码。
4. 补充代价：类数量增加、调用链变长、过度设计会降低可读性。
